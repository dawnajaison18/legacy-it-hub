01

Networking fundamentals

A network is devices that can talk to each other. Every device needs an address so traffic knows where to go, and boxes in the middle move that traffic to the right place. Almost everything is some version of "what's the address, and how does traffic get from A to B safely."

IP address

A device's address on the network, e.g. 192.168.1.50. Office networks use private ranges (192.168.x.x, 10.x.x.x) that only work inside the building.

Subnet mask

Defines how big a group of addresses is, e.g. 255.255.255.0. Devices in the same subnet talk directly; anything outside goes via the gateway.

Default gateway

The "exit door" — usually the router's IP. Traffic destined for anything not local is sent here.

MAC address

A device's permanent hardware address, e.g. 00:1A:2B:3C:4D:5E. Used to deliver traffic within the local network; IP is used between networks.

DHCP

Automatically hands out IP addresses when devices connect. A DHCP failure (no address, or a 169.254.x.x address) is a very common "no internet" cause.

DNS

Translates names into addresses — turns google.com into an IP. Symptom: a site won't load by name but pings fine by IP = DNS problem.

The mental model: a switch and router move traffic, a firewall judges it, DHCP assigns addresses, and DNS translates names. Keep those four verbs straight and most setups make sense.
02

The OSI & TCP/IP model

A layered map of how data travels. You rarely memorise all of it, but it's the framework everyone uses to locate a problem — "is this a layer 1 (cable) issue or a layer 3 (IP) issue?" The OSI model has 7 layers; the simpler TCP/IP model collapses them into 4.

7ApplicationWhat the user sees — HTTP, DNS, email, file sharing
6PresentationFormatting & encryption — TLS/SSL, file formats
5SessionOpening & maintaining connections between apps
4TransportReliable vs fast delivery — TCP & UDP, ports
3NetworkAddressing & routing between networks — IP, routers
2Data LinkLocal delivery on one network — MAC, switches, VLANs
1PhysicalThe actual signal — cables, Wi-Fi radio, connectors
Memory aid (top to bottom): "All People Seem To Need Data Processing." Troubleshoot from the bottom up — confirm the cable (1) before you suspect DNS (7).

04

IP addressing & subnetting

An IPv4 address is 32 bits, written as four octets (each 0–255). The address splits into a network portion (which network) and a host portion (which device). The subnet mask draws that dividing line.

Example: 192.168.1.50 /24 — the /24 means the first 24 bits (the first three octets, 192.168.1) are the network. The last octet (50) identifies the host. Everything sharing 192.168.1.x is on the same network.

Reserved addresses

Two addresses in every subnet are reserved and not usable by devices: the first is the network address (e.g. 192.168.1.0) and the last is the broadcast address (e.g. 192.168.1.255). That's why a /24 has 256 total addresses but only 254 usable.

06

IP address types

Private vs public

Private (192.168.x.x, 10.x.x.x, 172.16–31.x.x) work only inside your network. Public addresses are routable on the internet and assigned by your ISP.

Static vs dynamic

Dynamic addresses are assigned by DHCP and can change. Static addresses are set manually and stay fixed — used for servers, printers, and network gear.

APIPA — 169.254.x.x

A self-assigned address a device gives itself when DHCP fails. Seeing this is a red flag: the device never got a real address.

Loopback — 127.0.0.1

Always refers to "this device itself." ping 127.0.0.1 tests whether the local network stack is working at all.

IPv4 vs IPv6

IPv4 is the familiar 32-bit dotted format. IPv6 is a much larger 128-bit format (e.g. 2001:db8::1) created because IPv4 addresses ran out.

NAT

Lets many private IPs share one public IP to reach the internet — and as a side effect hides internal devices from the outside world.

Protocols: TCP vs UDP

Both carry data, but with different trade-offs. The choice is reliability vs speed.

TCP — reliable

Connection-oriented. Confirms delivery, re-sends lost data, keeps order. Used where accuracy matters: web, email, file transfer, remote desktop.

UDP — fast

Connectionless. No delivery guarantee, no re-sending — just speed. Used where a little loss is fine: voice/VoIP, video streaming, DNS lookups.

Wi-Fi & wireless

Wireless follows the 802.11 standards. The two practical things you'll tune are the band (range vs speed) and the security (protecting the network).

Frequency bands

BandRangeSpeedNotes
2.4 GHzLongerSlowerBetter through walls, but crowded & prone to interference
5 GHzShorterFasterLess interference; the everyday choice for most clients
6 GHzShortestFastestWi-Fi 6E / 7 — newest, very clean, needs modern hardware

Security standards

WPA3 use

The current standard — strongest encryption. Use it where all hardware supports it.

WPA2 ok

Still widely used and acceptable. The realistic minimum for any network today.

WEP / WPA avoid

Old and broken — trivially cracked. Never use for anything carrying real data.

Useful terms

SSID — the network's name. Channel — the specific frequency slice; overlapping channels between nearby APs cause slowdowns. Guest network — a separate SSID (ideally its own VLAN) that keeps visitors off internal systems. 802.11 a/b/g/n/ac/ax — the generations, also marketed as Wi-Fi 4, 5, 6, and 7.

Cabling & connectors

Wired connections are still the backbone. The key limits: copper Ethernet maxes out at 100 metres per run, and the cable category sets the speed.

CableMax speedNotes
Cat5e1 GbpsThe common baseline for desks & phones
Cat6up to 10 Gbps10 Gbps only on shorter runs (~55 m)
Cat6a10 Gbps10 Gbps over the full 100 m
Fiber optic10+ GbpsLong distance, immune to electrical interference — used for backbones & between buildings

RJ45

The standard 8-pin connector on Ethernet cables.

PoE

Power over Ethernet — delivers power and data over one cable. Powers APs, IP phones, and cameras without a separate adapter.

Straight-through vs crossover

Old distinction for which devices connect to which. Modern gear has Auto-MDIX, so almost any cable works either way now.

Patch panel

Where in-wall cables terminate in a rack, then patch to the switch. Good labelling here saves hours of troubleshooting.

11

VPN & remote access

A VPN (Virtual Private Network) creates an encrypted tunnel across the internet, so a remote device behaves as if it's safely on the internal network.

Remote-access VPN

One user (e.g. a staff member working from home) connects securely back to the office network.

Site-to-site VPN

Permanently links two locations' networks together over the internet.

Why it matters here: a VPN encrypts traffic in transit, so any patient information a remote staff member accesses is protected on the way — a key control for handling PHI outside the building under HIPAA.

Run these in Windows Command Prompt or PowerShell — your daily toolkit.

13

Diagnostic logic

Most connectivity problems come down to one layer. Check them bottom to top:

1

Physical / link — is it actually connected? Cable seated, Wi-Fi associated, link light on.

2

Address (DHCP) — does it have a valid IP? A 169.254.x.x address means DHCP failed and the machine self-assigned a useless address.

3

Gateway — can it reach the router? ping 8.8.8.8 works = connection is fine.

4

Names (DNS) — ping 8.8.8.8 works but ping google.com fails = it's a DNS problem, not a connection problem.

The one rule to remember: pings by IP succeed but pings by name fail → DNS. Neither works → check IP and gateway first with ipconfig.
14

Firewalls

A firewall controls what traffic is allowed in and out, based on an ordered rule set (ACL). Each rule says allow/deny [traffic] from [source] to [destination] on [port]. Rules are checked top to bottom and stop at the first match — so order matters.

Default deny

Most rule sets end with an implicit "deny everything else." Allow only what you need; block the rest. This is the secure starting stance.

Stateful

Remembers connections it has seen. When your PC requests a page, the reply is allowed back automatically — no separate return rule needed. Nearly all modern firewalls are stateful.

Inbound vs outbound

Separate rule sets. Inbound blocks unsolicited traffic from outside; outbound controls what your machines may send (stops malware "phoning home").

Host vs network

A network firewall sits at the edge protecting everything behind it; a host firewall (e.g. Windows Defender Firewall) runs on a single machine.

Why it matters here: firewall rules plus VLAN segmentation are a core part of demonstrating that systems holding patient data are shielded from the open internet and from less-trusted parts of the internal network — which maps directly onto HIPAA security expectations.
15

VLANs & network design

A VLAN splits one physical switch into multiple separate logical networks. You assign each switch port a VLAN ID (1–4094) — port 5 is "Staff," port 12 is "Guest" — and devices only see traffic within their own VLAN, even on shared hardware.

By design, VLANs can't talk to each other through the switch alone. To allow specific cross-VLAN traffic, it must pass through a router or layer-3 switch (inter-VLAN routing / "router on a stick") — and that routing point is exactly where firewall rules decide which flows are permitted.

Access port

Carries one VLAN. What a normal device — a PC or printer — plugs into.

Trunk port

Carries many VLANs at once using 802.1Q tags. The link between two switches, or switch-to-router.

A sensible segmentation pattern

Separate everything by default, then open only the paths that should exist:

VLAN 10 · Clinical / EHR VLAN 20 · Staff VLAN 30 · Guest Wi-Fi VLAN 40 · VoIP phones VLAN 50 · Printers / devices

Then firewall rules at the routing point allow only necessary flows — e.g. Staff may reach a specific server, Guest reaches nothing internal at all.
